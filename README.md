Собирает docx-отчет с решениями задач из курса на Stepik: берет условие, последнее
правильное решение и оформляет все по шаблону. Раньше это были сотни раз
«открыл окно, скопировал, вставил в ворд». Теперь это одна команда.

## История создания проекта

Этот проект вообще начинался как знакомство с пакетным менеджером uv,
да и в целом для развлечений, но вдруг... Но вдруг что?

Наверно всем людям на планете не нравится делать однотипные действия, наподобие: "Открыл окно.
Скопировал текст. Свернул окно. Вставил в ворд. Снова открыл окно. Ножницами сделал скриншот.
Свернул окно. Вставил...". Уже звучит скучно, не правда ли?

Прикол в том, что... такое и вправду существует. Прикинь, что тебе задали задачу,
в унике, где надо вот так вот работать и так около 400 итераций 💀. Не позавидуешь этому
"счастливчику".

Но жизнь так поворачивается, что ты все-таки становишься этим "счастливчиком".
Окей, вот как я решил справиться с этой проблемой.

## Что умеет

- по номеру раздела (лабы) находит все уроки и шаги курса через API Stepik;
- для каждой задачи с кодом берет условие и **последнее правильное решение** (`correct`);
- вставляет код в docx текстом с подсветкой синтаксиса (Pygments), его можно копировать и искать по документу;
- подпись «Листинг 2.N» стоит над кодом и не отрывается от него при переносе страницы;
- старый режим с картинками (Pillow, JetBrains Mono) включается флагом `--images`;
- для каждого раздела можно положить свой шаблон `assets/<номер>-template.docx`;
- в конце печатает, сколько задач попало в отчет и сколько это заняло времени.

## Быстрый старт

1. `pip install uv`, [гайд по установке uv](https://docs.astral.sh/uv/getting-started/installation/).
2. `git clone https://github.com/viteax/stepik-report-creator.git`
3. `cd stepik-report-creator`
4. `uv sync`
5. Создай приложение на https://stepik.org/oauth2/applications/ со следующими настройками:

   | Поле                       | Значение             |
   |----------------------------|----------------------|
   | Client type                | confidential         |
   | Authorization grant type   | client-credentials   |

6. `cp .env.example .env`
7. Открой `.env` и вставь `CLIENT_ID` и `CLIENT_SECRET` из созданного приложения.
8. `uv run main.py 7`, где `7` — номер раздела (лабы).

Готовый файл появится в папке `my_docs/`. Скажем нет повторяющимся действиям!

## Аргументы командной строки

```bash
uv run main.py            # номер раздела спросит интерактивно
uv run main.py 7          # собрать отчет по 7-му разделу
uv run main.py 7 --course 12345   # другой курс Stepik
uv run main.py 7 --images         # код картинками вместо текста
```

## Как это устроено

```
main.py            точка входа: аргументы, обход уроков, замер времени
oauth.py           получение токена по client-credentials
clients/stepik.py  запросы к API Stepik (курс, раздел, уроки, шаги, решения)
clients/word.py    запись в docx (заголовки, картинки, подписи)
docx_code.py       код текстом с подсветкой: стиль Code, рамка, заливка (Pygments)
logic.py           разбор условия задачи и рендер кода в картинку
models/            pydantic-модели ответов API и внутренних данных
assets/            шаблоны docx и шрифт
```

Решение берется из эндпоинта `/api/submissions?step=<id>`: из списка попыток выбирается
последняя со статусом `correct`. Если правильной попытки нет, задача пропускается.
На каждую задачу уходит несколько запросов к API, поэтому время работы зависит от сети
и числа задач в разделе. Замер на реальных данных: один отчет собирается за ~2 секунды
(`uv run main.py 7`).

## Создаем кастомные настройки

Этот раздел поможет понять что надо менять, чтоб закастомить вид итогового отчета.

### Структура ворда

Существует шаблон, находящийся в папке *assets/template.docx*, на нем строится документ.
Для конкретного раздела можно положить рядом файл *assets/<номер>-template.docx*,
он будет использован вместо общего. Поменять структуру добавления решений в документ можно
в файле *clients/word.py*.

### Рендер кода решения

Код вставляется текстом: стиль `Code` и подсветка Pygments живут в отдельном модуле *docx_code.py* (шрифт и размер – аргументы `ensure_code_style`, цветовая схема и язык – аргументы `add_code`). Модуль не зависит от остального проекта, его можно забрать в свой генератор документов.
Режим `--images` рисует код картинкой, это делается в файле *logic.py* через либу *Pillow*.
Здесь фантазия никак не ограничивается, твори! Можно поменять фон, шрифт, размер шрифта,
цвет шрифта, добавить цифры к строкам, раскрасить определенные слова, все что угодно.

## Тесты

```bash
uv run pytest -m "not network"                 # без сети и ключей (это же запускает CI)
uv run pytest -m "not network" --cov           # то же с покрытием
uv run pytest                                  # все, включая тесты с реальным API
```

Тесты с пометкой `network` обращаются к настоящему API Stepik, для них нужен заполненный `.env`.

## Ограничения

- нужен собственный OAuth-ключ Stepik, отчет строится от имени твоего приложения;
- обрабатываются только шаги типа `code`;
- заголовки в документе («2.N», «Листинг 2.N», «Заключение») заточены под один формат отчета;
- подсветка рассчитана на Python;
- условие разбирается эвристикой: берутся абзацы до «Формат входных данных».
